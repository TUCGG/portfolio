## 문제

오픈소스 CaSS를 기반으로 한 v1은 문서 서명과 업무 규칙을 화면 코드가 맡고, 화면이 범용 저장 API를 바로 불렀습니다. 그래서 권한과 데이터 검증을 서버 한곳에서 관리하기 어려웠습니다.

운영 중인 데이터는 바꿀 수 없었습니다. CaSS JSON-LD 필드, Elasticsearch 인덱스와 매핑, 기존 키, LRS·LCMS·포털 연동 형식을 그대로 유지해야 했습니다.

## 역할

2025년부터 v1 서버(CaSS 포크)와 학습맵 뷰어를 유지보수하며 기능을 추가해 왔고, v2는 설계부터 맡았습니다. v2 저장소 커밋 147개 중 146개를 작성했습니다.

## 해결

- SAML 통합 로그인으로 사용자를 식별하고, 서명에 쓰는 키는 서버에서만 다룹니다.
- 범용 저장 API 대신 Framework, Competency, Relation, Level, Directory 같은 도메인 API를 만들었습니다. 모든 쓰기는 권한 확인 → 버전 갱신 → 서버 서명 → 저장 순서를 거칩니다.
- 삭제 전에 참조를 확인하고, 역량은 연결 해제와 완전 삭제를 나눴습니다.
- 서버는 24개 도메인 모듈로 나누고 `main.ts`에서 조립합니다. 클라이언트는 route → page → hook → repository → API 한 방향으로만 흐릅니다.
- IMS CASE, CSV, 텍스트 가져오기를 서버에서 같은 형식으로 정규화하고, OpenAPI 문서를 API 계약으로 씁니다.
- 관계 차트를 three.js GraphChart로 바꾸고 배치 계산 속도를 개선했습니다. 2D와 3D를 오갈 때 선택한 노드를 화면 가운데에 유지합니다.

## 결과

- 기존 운영 데이터를 재색인 없이 그대로 읽고 씁니다.
- 테스트 파일 약 170개, 도메인마다 스펙 문서 1개씩을 두었습니다.
- 기존 문서 소유권은 자동으로 옮기지 않았고, v1의 일부 공유 기능은 뺐습니다. 이 결정은 설계 기록에 남겼습니다.
